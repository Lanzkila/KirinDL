# KirinDL v3.1.7

### Smarter New Update trigger • About recovery • improved update popup

KirinDL v3.1.7 focuses on making app updates easier to notice, easier to recover when dismissed, and cleaner to review before downloading.

The update flow now follows a Komikku-inspired approach: KirinDL checks for a newer release when the main app interface starts, automatically presents the New Update prompt when appropriate, limits repeated automatic checks, and keeps a manual recovery path inside **About** if the popup was dismissed or missed.

## ✦ Highlights

- Reworked the automatic **New Update** trigger
- Added startup update checking when KirinDL enters the main app interface
- Added a cooldown for automatic update checks to reduce repeated GitHub requests
- Removed permanent suppression of a release after its popup was shown once
- Added manual recovery for missed or dismissed updates from **About**
- Improved the **App Update** card inside About
- Improved the New Update popup layout
- Improved Installed → Available version presentation
- Added clearer Stable / Pre-Release identification
- Improved long release-note scrolling
- Improved release-note rendering for headings, bullets, numbered items, and links
- Preserved background APK download through Android DownloadManager

## ✦ New Update Trigger

KirinDL now checks for a newer release when the main app UI becomes available.

When a newer release is found, the New Update interface can open automatically without requiring the user to first enter Settings.

Automatic checks are throttled so repeatedly opening KirinDL does not continuously request the GitHub Releases API.

The normal automatic-check cooldown is approximately:

```text
48 hours
```

Unlike the previous popup logic, showing a release once no longer permanently suppresses that same release.

If the user has not updated yet, KirinDL can present the update again after the automatic-check interval.

## ✦ Missed Update Recovery from About

If the automatic popup was closed, dismissed, or missed, the update can be checked again manually from:

```text
Settings
→ About
→ App Update
```

The About update action performs a fresh manual check and is not blocked by the normal automatic-check cooldown.

When a newer release is available, KirinDL opens the same New Update interface again so the version, release notes, and update action can be reviewed immediately.

## ✦ Update Popup Improvements

The New Update interface now presents the installed and available versions more clearly.

It includes:

- Installed KirinDL version
- Available KirinDL version
- Stable or Pre-Release channel
- Release publication information
- Available APK variants
- Release notes
- Update / release-page action

Long release notes scroll inside their own content area so the main update information and controls remain easier to reach on smaller phones.

Pre-Release version suffixes are preserved instead of being trimmed down to the Stable version number.

## ✦ APK Variants

KirinDL continues to publish separate APK choices for Stable and Pre-Release builds.

### ARM64

Recommended for most current Android phones and tablets using `arm64-v8a`.

### Universal

Use Universal when device architecture is unknown or broader ABI compatibility is required.

Stable release assets remain:

```text
KirinDL-ARM64-Release.apk
KirinDL-ARM64-Release.apk.sha256
KirinDL-Universal-Release.apk
KirinDL-Universal-Release.apk.sha256
```

## ✦ Stable and Pre-Release Channels

The existing KirinDL channel separation remains unchanged.

Stable uses:

```text
com.kirin.downloader
```

Pre-Release uses:

```text
com.kirin.downloader.prerelease
```

This keeps Kirin Pre-Release installable beside the Stable app.

## ✦ Background APK Download

When a downloadable KirinDL APK is available, the updater can hand the file to Android's DownloadManager.

The APK is downloaded in the background while installation remains a normal user-controlled Android action.

Update files are stored under:

```text
Download/KirinDL/Updates/
```
