# KirinDL v3.2.0.9

### Fix opening completed downloads from KirinDL

- Play, download history, completed notifications, and Share now use the same local-file handoff with an explicit MIME type, content URI, ClipData, and temporary read permission.
- Raw paths, `file://` paths, and existing content/document URIs are supported. HTTP source URLs are never substituted for a missing local file.
- A generic document MIME type falls back to the filename, including MKV, M4A, and Opus.
- Completed download targets now contain finished audio/video files only. Play no longer selects HLS/DASH manifests, metadata, images, subtitles, empty files, or incomplete download sidecars.
- Match the media filename rather than an arbitrary parent path; preserve chapter downloads and prefer the main merged file, then newer files with the same title.
- SD-card transfers retain supplementary files while returning media files as the completed Play targets.
- Retains the original About page and YouTube/cookie changes from v3.2.0.8.

## Validation

- Seven media-selection regression tests and six Android 11 (API 30) file-intent tests cover readable FileProvider URIs, encoded names, `file://`, existing content URIs, SD-card document handling, Share, and rejection of missing/remote paths.
- The release workflow also runs the existing YouTube recovery, extractor-argument, and cookie tests, builds all release APKs, and verifies signing, versions, package names, and checksums before publication.
- The reported phone has not been tested here. These changes address the app's local-file handoff and output selection; resolution of the reported playback message still needs confirmation on that phone.
- YouTube account/bot verification remains dependent on the session and network. This release does not claim a new fix for that service response.
