# KirinDL v3.1.9

### Stable fixes • Preset/Custom • Converters • Gallery DL • Search/Feed • yt-dlp updater

KirinDL v3.1.9 consolidates the recent Stable fixes into the next release build. This release keeps the current KirinDL feature set while correcting the download popup flow, restoring the intended Stable yt-dlp updater behavior, and carrying forward the recent converter, Gallery DL, Search/Global Feed, and Download Center fixes.

## ✦ Highlights

- Fixed the **Preset / Custom** download popup flow where Custom could fail while fetching video information.
- Added a controlled fallback fetch path for Custom format selection when the primary metadata request fails.
- Fixed Kotlin source-generation/escaping issues that could cause the Stable build to fail during compilation.
- Restored **Media Converter** and **Manga Converter** support with their current output-directory integration.
- Restored **Kirin Search** and **Global Feed** after the earlier Stable cleanup investigation.
- Preserved the current **Gallery DL** engine and its latest logic instead of replacing it with the older yt-dlp engine.
- Fixed the **Download Center / Paste / Autofill** dialog-state behavior so returning to the input flow resets correctly.
- Restored the Stable **yt-dlp updater** behavior to the Sealplus-style update flow used by the fork.
- Added a one-time migration from the earlier Kirin yt-dlp recovery setting so automatic yt-dlp updates can resume correctly.
- Preserved Stable / Pre-Release separation and the existing ARM64 / Universal build coverage.

## ✦ Preset / Custom Download Fix

The Custom Video and Custom Audio actions require video metadata before the format-selection screen can be displayed.

v3.1.9 keeps the normal metadata request as the primary path. If that request fails, KirinDL retries once with a reduced set of optional extraction settings before showing the error state.

This is intended to make the Custom popup more tolerant of extractor responses without changing the normal Preset download path.

## ✦ Build / Compile Fixes

The recent Stable patch chain also contained Kotlin source escaping corrections that are now included in the v3.1.9 release patch.

The affected generated strings are kept as valid Kotlin string literals so the project can proceed through the normal Gradle compilation stage.

## ✦ Media & Manga Converters

The current converter additions remain included:

- Media Converter
- Manga Converter
- Converter preferences
- Converter output-directory support
- Converter resources and engines

The converter implementation remains separate from the normal yt-dlp download flow.

## ✦ Gallery DL

Gallery DL keeps its own current engine and update path.

The v3.1.9 patch does not replace the current Gallery DL engine with the older Stable yt-dlp logic. The Gallery DL filtering and site-memory behavior restored during the Stable logic work is retained.

## ✦ Search & Global Feed

Kirin Search and Global Feed are retained in v3.1.9 after the earlier investigation showed that removing them was not required as the final Stable direction.

## ✦ Download Center / Paste & Autofill

The download sheet state is reset when the dialog is hidden so reopening the Download Center does not remain stuck in a previous sheet state.

The existing Compose text-menu filtering remains applied to the relevant input field behavior.

## ✦ Sealplus-Style yt-dlp Updater

The Stable updater is restored to the updater pattern used by the Sealplus fork:

- Only update while the downloader is idle.
- Respect the **Auto Update** preference.
- Respect network availability.
- Respect the configured update interval.
- Run the actual yt-dlp update through the existing `UpdateUtil.updateYtDlp()` path.
- Return the downloader state to Idle after the update attempt.

A one-time migration detects the older Kirin recovery preference and re-enables automatic yt-dlp updating while resetting the updater timestamp.

This avoids permanently leaving Stable on the earlier recovery-only updater behavior.
