# KirinDL v3.2.0.8

### Restore the original About page and improve YouTube session recovery

## About

- Restored the About cards from v3.1.9.1: App Update, Automatic Updates, View Onboarding, README, Releases, Sponsor, Credits, and the installed version/package footer.
- Reconnected the original navigation destinations and retained access to Tools.
- The App Update card uses the current persistent update state.

## YouTube and cookies

- Applied the saved **Extractor args** setting to normal metadata, playlist, comment, and download requests. This field previously saved its value without sending it to yt-dlp.
- Merge extractor options so subtitle, comment, and supplied PO-token options survive; an explicitly configured player client is preserved during recovery.
- On a bot verification response, try IPv4 if no address family was explicitly selected. This is temporary and does not alter saved preferences. If IPv4 cannot connect, keep the original verification diagnosis.
- Added **Sign in / cookies** to YouTube verification errors in the format dialog and download actions. It opens the existing cookie settings with a YouTube profile available for browser sign-in or manual import.
- Manual retry uses the current cookie switch and user agent, while keeping selected download and format settings.
- Format discovery retains login cookies and the selected network route. It no longer launches a second anonymous probe after account/bot verification.
- Bot verification is not treated as a transient network error merely because the engine also reported a timeout warning.
- Keep the existing HttpOnly cookie parser, atomic cookie refresh, and bounded recovery.

## Validation and limits

- Recovery, extractor-argument, and Netscape-cookie regression tests are required by the release workflow.
- The Android release workflow builds, signs, and verifies all APKs before publication.
- The reported video returned playable formats during a probe from the development network. The reported Android 11 phone and its YouTube session have not been tested here. Account or network verification may still require valid cookies; this release does not claim to remove YouTube restrictions.
- Startup diagnostics and the native downloader/runtime versions remain in place.
