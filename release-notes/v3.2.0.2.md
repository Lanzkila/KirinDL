# KirinDL v3.2.0.2

### Pre-release testing build

KirinDL v3.2.0.2 is the next testing build after v3.2.0. It can be installed **directly over v3.2.0**; no intermediate v3.2.0.1 installation is required.

> **Testing note:** v3.2.0 remains the recommended Stable release while v3.2.0.2 is being tested. If this build causes a device- or site-specific problem, return to v3.2.0.

## ✦ App update checker

- Added full four-part version comparison for builds such as `3.2.0.2`.
- Stable users ignore GitHub Pre-release builds.
- Pre-release testers can see both Stable and Pre-release builds and receive whichever valid KirinDL version is newer.
- Automatic checks now remember the installed KirinDL version and selected update channel.
- Installing a different KirinDL version forces a fresh update check instead of inheriting the previous build's cooldown.
- Switching Stable / Pre-release channel forces a fresh check even if the normal timer has not expired.
- Failed GitHub/network checks are no longer recorded as a successful "last checked" state.
- Automatic checks use a one-day cooldown only when the installed version and selected channel are unchanged.

## ✦ Update download and install flow

- In-app updates use Android Download Manager.
- KirinDL remembers the app-update Download Manager job.
- When the APK finishes downloading, KirinDL hands it to Android's package installer.
- If **Install unknown apps** permission is required, KirinDL opens the Android permission page and resumes the installer flow afterward.
- An **Update ready** notification is posted as a fallback on Android versions that block background activity launches.
- A release signed with the same KirinDL key updates/overwrites the installed app instead of creating a second installation.
- Android still requires the normal package-install confirmation.

## ✦ Media progress

- Fixed Media progress occasionally moving backward, for example `22% → 21% → 22%`, from slightly out-of-order yt-dlp DASH/fragment callbacks.
- Progress is monotonic within one transfer stream.
- A real new stream such as Video → Audio can still reset normally.
- Video, Audio, Fragment, Merge, Processing and Moving remain separate transfer phases.
- Compose progress refresh is reduced from 200 ms to 100 ms for a more responsive badge.
- Notification updates remain throttled separately to avoid unnecessary Android IPC load.

## ✦ Bilibili rollback

- Removed the dedicated Bilibili transfer profile that caused slower behavior on some devices.
- Removed Bilibili-specific Auto / Balanced / Fast / Custom fragment tuning.
- Removed the Bilibili-only Aria2 cap, timeout, retry override and adaptive previous-speed logic.
- Removed the unused Bilibili speed controls and stale Smart Download profile references.
- Bilibili remains available through the normal yt-dlp flow.
- Existing Bilibili search/discovery support is retained.

## ✦ Release notes popup

- Cleaner heading and list spacing.
- Duplicate version headings are suppressed.
- Blockquotes render as highlighted notes.
- Nested lists and code blocks are formatted more cleanly.
- Four-part KirinDL versions display correctly.
