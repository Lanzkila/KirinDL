# KirinDL v3.2.0.11

Pre-release · 13 October 2026

## Bilibili recovery

- When a video connection closes unexpectedly, refresh its playback information and try up to two backup URLs supplied by Bilibili for the same stream.
- Keep the selected format, downloader, cookies and partial files during recovery. Completed audio can be reused when retrying an interrupted video.
- Bound recovery attempts so an unavailable stream ends with a visible error instead of repeating indefinitely.
- Recognize aria2 transport failures even when the final error only reports its exit code.

## Progress and diagnostics

- Track progress by filename so retrying a video does not mislabel it as audio. Audio completion remains separate from merging and overall task completion.
- Hide internal stage markers in Download Center and show a Retrying stage during recovery.
- Add a Log action in Download Center and the media task action sheet, available while a task is active. Recent logs are kept for the current app session, with signed URL queries and credential headers redacted.

## Validation

The offline engine regression reproduces an interrupted video followed by a completed audio download, resumes the video through a backup URL, verifies the recovered bytes and checks that FFmpeg produces both audio and video tracks. Android recovery, cancellation, progress, logging and existing playback/YouTube tests gate the APK build.

This is a trial recovery build. Downloads through Bilibili's live CDN still need confirmation on affected devices and networks. It does not restore the removed Bilibili speed profile or change YouTube's download policy.
