# KirinDL v3.2.3.1

Prepared · 15 November 2026

## App Update Channel Detection

- Match the update-channel selection behavior used by YTDLnis.
- Detect when the installed version corresponds to a GitHub Pre-release release.
- Force Pre-release installations to update to the latest Stable release, even when its version number is lower.
- Keep the older Stable offer cached while the Pre-release build remains installed.
- Recheck the installed tag on each app start so promotion of that same tag to Stable clears the forced prompt.
- Do not permanently remember Dismiss for a forced Stable migration; offer it again until the installed tag becomes Stable.
- Stop forcing the Stable migration after a Stable APK is installed.
- Keep normal Stable/Pre-release channel selection for Stable installations.
- In Stable mode, ignore Pre-release releases.
- Ensure the startup Updates popup receives results from the shared automatic update check.
- Preserve the separate **About → App Update** entry point.

## Startup Update Dialog

- Replace the separate startup Updates inbox card with one direct release dialog, following YTDLnis's app-update dialog flow.
- Separate **Cancel** (close this prompt / cancel the active download) from **Ignore** (remember the selected release).
- Keep forced Stable migration prompts active until the installed Pre-release tag is promoted or a Stable build is installed.
- Keep the About manual update entry point independent.
- Credit the adapted YTDLnis source in the Kotlin files and README.

## Regression Coverage

- Cover forced migration from an installed Pre-release to an older Stable version.
- Verify an already installed Stable version is not forced back to an older Stable release.
- Verify the forced Stable offer stays cached until the installed version becomes Stable.
- Verify the forced Stable prompt is not permanently silenced by Dismiss.
- Cover normal Stable/Pre-release channel selection.
- Include app update channel-selection tests in the Release workflow.
