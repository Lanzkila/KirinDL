# KirinDL v3.2.0.6

### Startup crash diagnostics • Pre-release testing

Based on the proven KirinDL v3.2.0.3 app source plus targeted startup hardening. This is a testing build, not a claim that the first-launch crash is fixed.

## Changes

- Reverted unrelated v3.2.0.4/.5 app changes to the v3.2.0.3 base before applying focused crash diagnostics.
- Install the crash handler at the start of App initialization, before MMKV, Koin, and updater work.
- Add limited retry for transient MMKV initialization errors, without clearing user data.
- Make non-critical updater state migration, dynamic colors, and notification initialization non-fatal.
- Record startup stages and preserve the last captured Java crash report in app-private storage.
- Recover an unfinished previous startup breadcrumb as a diagnostic hint for possible early/native termination (not proof of a crash).
- Add **Settings → Troubleshooting → Copy Last Crash Report**.
- Simplify **Settings → About** to **Tools**, **Stable**, and **Pre-release**.
- Keep the other application features from the v3.2.0.3 baseline.

## Test checklist

1. Install over the existing KirinDL build using the same signing key, without clearing data.
2. Launch the app three times; note whether it crashes on the first, second, or third attempt.
3. If it crashes but later opens, go to Settings → Troubleshooting → **Copy Last Crash Report** and share that report for diagnosis.
4. Verify Tools, Stable/Pre-release release notes, and an audio/video download.

> The Android "KirinDL keeps stopping" popup itself cannot show a Java stack trace. If the app cannot open at all, Android logcat will be needed to diagnose a native or pre-handler crash.
